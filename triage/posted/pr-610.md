Fixes #527, fixes #466.

On pages whose CSP has a `style-src` (or `default-src`) without `'unsafe-inline'`, Firefox draws no lasso: no outline, and the counter shows up in the top-left corner of the page. Examples: mangaupdates.com (`style-src 'self' … 'nonce-…'`), FreshRSS (`default-src 'self'`) and arewewaylandyet.com (`style-src 'self'`). The cause is in my comment on #527: Firefox applies the page's CSP to the `<style>` element that `SelectionRect` builds through `innerHTML` ([bug 1267027](https://bugzilla.mozilla.org/show_bug.cgi?id=1267027)) and only exempts styles a content script sets itself ([bug 1415352](https://bugzilla.mozilla.org/show_bug.cgi?id=1415352)). The unstyled boxes can also cover the links, so the obscured check drops them: on the test page below, master selected 0 links in Firefox.

### Change

- `SelectionRect` and `SvgOverlay` set their styles with `style.cssText`, with the same declarations the `<style>` element had. No `<style>` element and no `style` attributes anymore, the highlight rects included. A page's CSP never applies to the CSSOM, not even to the page's own scripts, so this doesn't depend on Firefox's exemption for content scripts. Inline styles also win over the page's own CSS rules, except `!important` ones (the #567 test still passes).
- `ElementIndexer.Search()` restores the container's `z-index` after the obscured check instead of clearing it, which would now remove the inline `z-index: 999999`. `test.ElementIndexer.js` now checks that it comes back.
- Nothing changes visually: same colors, outline and counter, and on pages without a CSP the counter lands on the same pixel as before.
